# Contributing to MURPH

## Development principles

- Keep changes focused and small.
- Verify hardware assumptions before implementing them.
- Do not commit credentials or private configuration.
- Do not commit generated build artifacts.
- Document hardware-specific settings and important design decisions.
- Test changes on the target hardware whenever possible.

## Commit messages

Use clear, descriptive commit messages.

Examples:

- `chore: initialize project structure`
- `feat: add sensor support`
- `fix: handle sensor communication errors`
- `docs: document hardware connections`
